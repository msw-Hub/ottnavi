# Review

가장 최근 커밋 이후 지금까지 쌓인 변경사항(스테이지 여부 무관)을 대상으로 코드 리뷰를 수행합니다.

## 사용법

```
/git-review                    # 이전 커밋 ~ 현재 작업 내용 전체 리뷰
/git-review [파일 경로]         # 특정 파일만 리뷰
```

## 리뷰 범위

- `git diff HEAD` 기준: 마지막 커밋 이후 변경된 모든 내용 (staged + unstaged 전부 포함)
- 아직 커밋되지 않은, 지금 커밋하면 반영될 변경사항이 대상 (그 이전 히스토리는 다루지 않음)

## 리뷰 관점

1. **로직 오류** — 의도한 대로 동작하지 않을 가능성이 있는 부분
2. **예외/엣지 케이스 누락** — null 처리, 빈 값, 경계값 등 놓친 케이스
3. **일관성** — 프로젝트 기존 코드 스타일·네이밍 컨벤션과 어긋나는 부분
4. **중복/과도한 복잡도** — 이미 있는 로직을 재작성했거나, 불필요하게 복잡한 부분
5. **보안** — 인증/인가 누락, SQL Injection 가능성, 민감 정보 로깅 등
6. **민감 정보 노출 검사 (최우선)** — 아래 항목이 diff에 그대로 포함되어 있는지 반드시 확인한다
   - API 키, 토큰, 시크릿 (AWS/DB/OAuth 등)
   - 비밀번호, 개인 계정 정보가 하드코딩된 값
   - `.env`, `application*.yml/properties`, `*.pem`, `*.key` 등 설정·인증서 파일 자체가 추가된 경우
   - DB 접속 정보(호스트, 포트, 계정)가 코드나 설정 파일에 평문으로 박혀 있는 경우
   - 이 항목에서 하나라도 발견되면 **다른 지적 사항과 별도로, 리뷰 맨 위에 최우선 경고로** 표시한다

## 프로세스

1. `git status`로 현재 스테이지/변경 상태 확인
2. `git diff HEAD`로 마지막 커밋 이후 전체 diff 확보 (인자로 파일 경로가 주어지면 해당 파일로 한정)
3. **민감 정보 노출 항목(6번)부터 먼저 검사한다** — 발견되면 리뷰 결과 최상단에 경고로 표시
4. 나머지 변경된 파일별로 1~5번 관점에서 검토
5. 문제 없는 파일은 짧게 "이상 없음"으로 넘어가고, 문제 있는 부분만 구체적으로 짚는다

## 출력 형식

```
## ⚠️ 민감 정보 경고 (발견 시에만 표시)
- <파일 경로>: <어떤 항목이 노출됐는지>
  조치: 커밋 전 반드시 제거하거나 .env/시크릿 매니저로 이동할 것

## 리뷰 요약
변경 파일: N개 | 지적 사항: N건 (심각 N / 권장 N)

## <파일 경로>
- [심각] <문제 설명> — <라인 또는 위치>
  제안: <구체적인 수정 방향>
- [권장] <문제 설명>
  제안: <구체적인 수정 방향>

## 종합 의견
<커밋해도 괜찮은지, 먼저 고쳐야 할 게 있는지 한 줄 결론>
```

## 참고사항

- 코드를 직접 수정하지 않는다 (리뷰 의견 제시까지만) — 수정은 사장님이 직접 하거나, 별도로 요청했을 때만 진행
- 사소한 스타일(줄바꿈, 세미콜론 등)은 포맷터가 처리할 영역이므로 지적하지 않는다
- 지적 사항이 없으면 억지로 만들어내지 않고 "리뷰 결과 문제 없음"으로 끝낸다
