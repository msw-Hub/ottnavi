## 2. 동작 흐름

앱이 뜨면 Flyway가 `V1 → V2 → V3 → V4` 순서로 아직 안 적용된 파일만 실행한다. `application.yml`에 이미 `ddl-auto: validate`(엔티티와 DB 구조가 다르면 기동 실패)와 `batch.jdbc.initialize-schema: never`(Spring Batch가 테이블을 자동으로 만들지 않음)가 들어 있어서, `BATCH_*`는 V4가 만든다. V2~V4가 만드는 테이블에는 대응하는 엔티티가 아직 없어 `validate`가 검사하지 않는다. 기존 `OttService` 엔티티가 V1의 `ott_service`만 검증한다.

시드는 `INSERT ... SELECT ... JOIN ott_service`로 넣는다. 서비스 번호(id)를 직접 쓰지 않고 `code`(`NETFLIX` 등)로 찾기 때문에 V1이 어떤 번호를 줬든 안전하다. 반대로 V1의 코드가 바뀌면 **오류 없이 0행이 들어가므로** 테스트가 8행인지 확인한다.

DB가 막아 주는 잘못된 데이터는 이렇다. 테스트와 1:1로 대응한다.

| 제약 | 막는 것 |
|---|---|
| `uk_title_media_tmdb` | 같은 종류의 같은 TMDB ID 중복(영화 100과 드라마 100은 허용) |
| `uk_watch_unit_title_season` + `NULLS NOT DISTINCT` | 영화(시즌 NULL)를 한 작품에 둘 넣기. 일반 UNIQUE는 NULL끼리 다른 값으로 봐서 못 막는다 |
| `ck_watch_unit_season` | 시즌인데 시즌 번호 없음 / 영화인데 시즌 번호 있음 |
| `ck_availability_unknown_reason` | 모름 상태인데 이유 없음 / 모름이 아닌데 이유 있음 |
| `uk_availability_unit_service` | 같은 시청 단위·서비스 조합 중복 |
| `ck_tmdb_provider_mapped` | 연결됨(MAPPED) 상태인데 서비스 없음 / 그 반대 |
| `uk_product_price_product_from`, `ck_product_price_monthly` | 같은 시작일 요금 중복, 음수 요금 |
| 마스터 FK(`NO ACTION`) | 시청 단위가 참조하는 작품 삭제(6개월 삭제는 Task 080에서 자식부터 지운다) |

## 3. 파일 ① `V2__create_catalog.sql` (전체)

```sql
-- V2: 작품·데이터 영역(ERD A). tmdb_provider(+시드), title, watch_unit, availability, availability_change, genre, title_genre, title_cast (Task 033)
-- 수집 배치만 쓰고 공개 API·계산 엔진이 읽는다. NULL 표기가 없는 컬럼은 NOT NULL이다(ERD 머리말).

-- TMDB 제공처와 우리 서비스의 매핑. provider_id는 TMDB 값을 그대로 PK로 쓴다
CREATE TABLE tmdb_provider (
	provider_id    INT          PRIMARY KEY,                      -- TMDB 값 그대로(8, 1796 등)
	tmdb_name      VARCHAR(100) NOT NULL,                         -- TMDB 원본 라벨. 판정에 쓰지 않는다
	logo_path      VARCHAR(200),
	mapping_state  VARCHAR(20)  NOT NULL DEFAULT 'UNMAPPED',      -- UNMAPPED / MAPPED / IGNORED
	ott_service_id BIGINT       REFERENCES ott_service (id),      -- MAPPED일 때만 값이 있다
	tier           VARCHAR(20)  NOT NULL DEFAULT 'STANDARD',      -- STANDARD / AD
	first_seen_at  TIMESTAMPTZ  NOT NULL DEFAULT now(),
	created_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
	updated_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
	CONSTRAINT ck_tmdb_provider_state CHECK (mapping_state IN ('UNMAPPED', 'MAPPED', 'IGNORED')),
	CONSTRAINT ck_tmdb_provider_tier CHECK (tier IN ('STANDARD', 'AD')),
	CONSTRAINT ck_tmdb_provider_mapped CHECK ((mapping_state = 'MAPPED') = (ott_service_id IS NOT NULL))
);
CREATE INDEX idx_tmdb_provider_service ON tmdb_provider (ott_service_id);

-- 작품(영화·드라마 공통). TMDB ID는 영화와 드라마가 겹칠 수 있어 (media_type, tmdb_id)로 유일하게 한다
CREATE TABLE title (
	id                BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	media_type        VARCHAR(10)  NOT NULL,                      -- MOVIE / TV. API는 소문자 movie/tv(변환은 도메인 enum)
	tmdb_id           INT          NOT NULL,
	title             VARCHAR(300) NOT NULL,                      -- 한국어 제목(없으면 원제)
	original_title    VARCHAR(300),
	overview          TEXT,                                       -- 줄거리. 비어 있을 수 있다
	overview_lang     VARCHAR(5),                                 -- ko / en. 영어로 대체했는지 표시
	release_date      DATE,                                       -- 영화 개봉일 / 드라마 첫 방영일
	poster_path       VARCHAR(200),
	backdrop_path     VARCHAR(200),
	original_language VARCHAR(10),
	tv_status         VARCHAR(30),                                -- 드라마만(Returning Series, Ended 등)
	popularity        NUMERIC(10, 3),                             -- 엔티티는 BigDecimal로 매핑한다(Double이면 validate가 막을 수 있다)
	vote_average      NUMERIC(4, 2),
	refresh_tier      VARCHAR(10)  NOT NULL DEFAULT 'WEEKLY',     -- DAILY(찜에 있음) / WEEKLY(나머지 후보)
	fetched_at        TIMESTAMPTZ  NOT NULL,                      -- 마지막 수집 시각. 6개월 갱신 규칙 점검에 쓴다
	created_at        TIMESTAMPTZ  NOT NULL DEFAULT now(),
	updated_at        TIMESTAMPTZ  NOT NULL DEFAULT now(),
	CONSTRAINT uk_title_media_tmdb UNIQUE (media_type, tmdb_id),
	CONSTRAINT ck_title_media_type CHECK (media_type IN ('MOVIE', 'TV')),
	CONSTRAINT ck_title_overview_lang CHECK (overview_lang IN ('ko', 'en')),
	CONSTRAINT ck_title_refresh_tier CHECK (refresh_tier IN ('DAILY', 'WEEKLY'))
);

-- 시청 단위(영화 1편 또는 시즌 1개). 찜·제공 상태·계산이 모두 이 테이블을 기준으로 한다
CREATE TABLE watch_unit (
	id                    BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	title_id              BIGINT       NOT NULL REFERENCES title (id),
	unit_type             VARCHAR(10)  NOT NULL,                  -- MOVIE / SEASON
	season_number         INT,                                    -- 영화는 NULL. 시즌 0(스페셜)은 수집하지 않는다
	tmdb_season_id        INT,                                    -- 시즌만
	name                  VARCHAR(300),                           -- 시즌 표시용(영화는 title 값을 쓴다)
	poster_path           VARCHAR(200),
	air_date              DATE,
	episode_count         INT          NOT NULL DEFAULT 1,        -- 전체 회차 수(영화는 1)
	aired_episode_count   INT          NOT NULL DEFAULT 1,        -- 방영된 회차 수
	total_runtime_min     INT          NOT NULL,                  -- 방영된 회차 runtime 합 / 영화 runtime
	runtime_missing_count INT          NOT NULL DEFAULT 0,        -- runtime이 비어 기본값을 쓴 회차 수
	runtime_estimated     BOOLEAN      NOT NULL DEFAULT FALSE,    -- 추정값 포함 여부(화면 "추정" 표시)
	fetched_at            TIMESTAMPTZ  NOT NULL,
	created_at            TIMESTAMPTZ  NOT NULL DEFAULT now(),
	updated_at            TIMESTAMPTZ  NOT NULL DEFAULT now(),
	-- 영화는 season_number가 NULL이라 일반 UNIQUE로는 영화 중복을 못 막는다. NULL끼리도 같은 값으로 본다
	CONSTRAINT uk_watch_unit_title_season UNIQUE NULLS NOT DISTINCT (title_id, season_number),
	CONSTRAINT ck_watch_unit_type CHECK (unit_type IN ('MOVIE', 'SEASON')),
	CONSTRAINT ck_watch_unit_season CHECK ((unit_type = 'SEASON') = (season_number IS NOT NULL)),
	CONSTRAINT ck_watch_unit_runtime CHECK (total_runtime_min >= 0)
);

-- 시청 단위 × 서비스 제공 상태. 서비스 단위로 집계해 저장한다
CREATE TABLE availability (
	id             BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	watch_unit_id  BIGINT       NOT NULL REFERENCES watch_unit (id),
	ott_service_id BIGINT       NOT NULL REFERENCES ott_service (id),
	status         VARCHAR(20)  NOT NULL,                         -- AVAILABLE / NOT_AVAILABLE / UNKNOWN
	unknown_reason VARCHAR(30),                                   -- UNKNOWN일 때만 값이 있다(NO_KR_DATA / STRUCTURAL_GAP)
	in_standard    BOOLEAN      NOT NULL DEFAULT FALSE,           -- STANDARD tier 제공처가 있었는지
	in_ad_tier     BOOLEAN      NOT NULL DEFAULT FALSE,           -- AD tier 제공처가 있었는지(광고형 판정)
	checked_at     TIMESTAMPTZ  NOT NULL,                         -- 마지막 확인 시각
	created_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
	updated_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
	CONSTRAINT uk_availability_unit_service UNIQUE (watch_unit_id, ott_service_id),
	CONSTRAINT ck_availability_status CHECK (status IN ('AVAILABLE', 'NOT_AVAILABLE', 'UNKNOWN')),
	CONSTRAINT ck_availability_reason CHECK (unknown_reason IN ('NO_KR_DATA', 'STRUCTURAL_GAP')),
	CONSTRAINT ck_availability_unknown_reason CHECK ((status = 'UNKNOWN') = (unknown_reason IS NOT NULL))
);

-- 제공 상태 변경 이력. 재계산·변경 알림의 입력이고 수집이 계속 쌓는 가장 빨리 커지는 테이블이다
CREATE TABLE availability_change (
	id               BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	watch_unit_id    BIGINT       NOT NULL REFERENCES watch_unit (id),
	ott_service_id   BIGINT       NOT NULL REFERENCES ott_service (id),
	before_status    VARCHAR(20),                                 -- 신규는 NULL
	after_status     VARCHAR(20)  NOT NULL,
	job_execution_id BIGINT,                                      -- Spring Batch 실행 ID(FK 없이 참조값만). 배치 밖(단건 수집)이면 NULL
	changed_at       TIMESTAMPTZ  NOT NULL DEFAULT now(),
	created_at       TIMESTAMPTZ  NOT NULL DEFAULT now(),
	updated_at       TIMESTAMPTZ  NOT NULL DEFAULT now(),
	CONSTRAINT ck_availability_change_before CHECK (before_status IN ('AVAILABLE', 'NOT_AVAILABLE', 'UNKNOWN')),
	CONSTRAINT ck_availability_change_after CHECK (after_status IN ('AVAILABLE', 'NOT_AVAILABLE', 'UNKNOWN'))
);
-- 실행별 "바뀐 작품" 조회와 실행 이력의 변경 건수 집계가 이 값으로 거른다(ERD 참조 컬럼 인덱스)
CREATE INDEX idx_availability_change_job ON availability_change (job_execution_id);

-- 장르(TMDB 장르 ID를 그대로 PK로 쓴다. 애니메이션은 16)
CREATE TABLE genre (
	id         INT          PRIMARY KEY,
	name       VARCHAR(50)  NOT NULL,
	created_at TIMESTAMPTZ  NOT NULL DEFAULT now(),
	updated_at TIMESTAMPTZ  NOT NULL DEFAULT now()
);

CREATE TABLE title_genre (
	title_id   BIGINT      NOT NULL REFERENCES title (id),
	genre_id   INT         NOT NULL REFERENCES genre (id),
	created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
	updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
	PRIMARY KEY (title_id, genre_id)
);
-- 장르로 작품을 찾을 때(고도화 후보)를 위한 인덱스는 지금 만들지 않는다. PK의 선두는 title_id다

-- 출연진(상위 10명만 저장). 인물 테이블은 두지 않는다
CREATE TABLE title_cast (
	id             BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	title_id       BIGINT       NOT NULL REFERENCES title (id),
	cast_order     INT          NOT NULL,
	person_tmdb_id INT          NOT NULL,
	name           VARCHAR(200) NOT NULL,
	character_name VARCHAR(300),                                  -- 계약 CastMember.character가 nullable이다
	profile_path   VARCHAR(200),
	created_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
	updated_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
	CONSTRAINT uk_title_cast_title_order UNIQUE (title_id, cast_order),
	CONSTRAINT ck_title_cast_order CHECK (cast_order >= 0)
);

-- Task 004 매핑표(2026-10-05 조사)를 시드로 넣는다. ott_service는 V1이 코드로 만든 7개 서비스를 코드로 찾는다.
-- 매핑되지 않은 KR 제공처 31개는 넣지 않는다. 수집이 발견하면 UNMAPPED로 저장하고 관리자가 매핑한다.
-- Coupang Play(1881)는 TV 목록에만 있다는 점을 수집 결과로 다시 확인한다.
INSERT INTO tmdb_provider (provider_id, tmdb_name, mapping_state, ott_service_id, tier)
SELECT v.provider_id, v.tmdb_name, 'MAPPED', s.id, v.tier
FROM (VALUES
	(8,    'Netflix',                   'NETFLIX',       'STANDARD'),
	(1796, 'Netflix Standard with Ads', 'NETFLIX',       'AD'),
	(337,  'Disney Plus',               'DISNEY_PLUS',   'STANDARD'),
	(1883, 'TVING',                     'TVING',         'STANDARD'),
	(97,   'Watcha',                    'WATCHA',        'STANDARD'),
	(356,  'wavve',                     'WAVVE',         'STANDARD'),
	(1881, 'Coupang Play',              'COUPANG_PLAY',  'STANDARD'),
	(350,  'Apple TV',                  'APPLE_TV_PLUS', 'STANDARD')
```

## 4. 파일 ② `V3__create_product.sql` (전체)

```sql
-- V3: 상품·요금 영역(ERD B). subscription_product, product_component, product_price (Task 033)
-- 요금제와 번들을 "구독 상품" 하나로 통일한다. 단품은 구성 서비스가 1개, 번들은 여러 개다.
-- 가격 시드는 넣지 않는다. 가격표는 관리자 화면(Task 061)에서 입력한다.

CREATE TABLE subscription_product (
	id           BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	name         VARCHAR(100) NOT NULL,                           -- 예: 넷플릭스 스탠다드. 계약 name은 최대 100자
	product_type VARCHAR(10)  NOT NULL,                           -- SINGLE / BUNDLE
	active       BOOLEAN      NOT NULL DEFAULT TRUE,              -- false면 판매 종료. 삭제하지 않는다. API에서는 isActive
	created_at   TIMESTAMPTZ  NOT NULL DEFAULT now(),
	updated_at   TIMESTAMPTZ  NOT NULL DEFAULT now(),
	CONSTRAINT ck_subscription_product_type CHECK (product_type IN ('SINGLE', 'BUNDLE'))
);

-- 상품에 포함된 서비스와 tier. MVP는 STANDARD 단품만 다룬다(AD tier와 번들은 2단계)
CREATE TABLE product_component (
	product_id     BIGINT      NOT NULL REFERENCES subscription_product (id),
	ott_service_id BIGINT      NOT NULL REFERENCES ott_service (id),
	tier           VARCHAR(20) NOT NULL DEFAULT 'STANDARD',       -- STANDARD / AD
	created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
	updated_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
	PRIMARY KEY (product_id, ott_service_id),
	CONSTRAINT ck_product_component_tier CHECK (tier IN ('STANDARD', 'AD'))
);
-- PK의 선두가 product_id라 서비스 쪽 조회는 따로 인덱스가 필요하다
CREATE INDEX idx_product_component_service ON product_component (ott_service_id);

-- 월 구독요금 이력. 종료일은 저장하지 않는다: 다음 줄 시작일의 전날까지 적용되고 마지막 줄은 계속 적용된다
CREATE TABLE product_price (
	id               BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	product_id       BIGINT       NOT NULL REFERENCES subscription_product (id),
	monthly_price    INT          NOT NULL,                       -- 원 단위 정수
	effective_from   DATE         NOT NULL,                       -- 적용 시작일(한국 날짜)
	last_verified_at TIMESTAMPTZ  NOT NULL,                       -- 관리자가 마지막으로 확인한 일시. 기본값을 두지 않는다
	created_at       TIMESTAMPTZ  NOT NULL DEFAULT now(),
	updated_at       TIMESTAMPTZ  NOT NULL DEFAULT now(),
	CONSTRAINT uk_product_price_product_from UNIQUE (product_id, effective_from),
	CONSTRAINT ck_product_price_monthly CHECK (monthly_price >= 0)
);
```

## 5. 파일 ③ `V4__create_batch_meta.sql` (전체)

Spring Batch 6.0.5가 jar 안에 가진 PostgreSQL 스키마를 그대로 옮긴 것이다(맨 위 주석 4줄만 우리가 붙임). **내용을 고치지 않는다.** 라이브러리 버전을 올리면 이 파일이 아니라 새 버전 파일로 변경분을 추가한다. 이름이 대문자인 것은 원본이 그렇기 때문이고, PostgreSQL은 따옴표 없는 이름을 소문자로 저장하므로 쿼리에서는 `batch_job_execution`처럼 써도 된다.

```sql
-- V4: Spring Batch 6.0.5 PostgreSQL 메타데이터(BATCH_*) (Task 033)
-- 출처: spring-batch-core-6.0.5.jar의 org/springframework/batch/core/schema-postgresql.sql을 그대로 옮겼다.
-- spring.batch.jdbc.initialize-schema=never라 라이브러리가 만들지 않으므로 Flyway가 만든다. 라이브러리 관리 테이블이라 서비스 테이블 24개에 세지 않는다.
-- Spring Batch를 올리면 이 파일을 고치지 않고 새 버전으로 변경분을 추가한다.

CREATE TABLE BATCH_JOB_INSTANCE (
	JOB_INSTANCE_ID BIGINT  NOT NULL PRIMARY KEY,
	VERSION BIGINT,
	JOB_NAME VARCHAR(100) NOT NULL,
	JOB_KEY VARCHAR(32) NOT NULL,
	constraint JOB_INST_UN unique (JOB_NAME, JOB_KEY)
) ;

CREATE TABLE BATCH_JOB_EXECUTION (
	JOB_EXECUTION_ID BIGINT  NOT NULL PRIMARY KEY,
	VERSION BIGINT,
	JOB_INSTANCE_ID BIGINT NOT NULL,
	CREATE_TIME TIMESTAMP NOT NULL,
	START_TIME TIMESTAMP DEFAULT NULL,
	END_TIME TIMESTAMP DEFAULT NULL,
	STATUS VARCHAR(10),
	EXIT_CODE VARCHAR(2500),
	EXIT_MESSAGE VARCHAR(2500),
	LAST_UPDATED TIMESTAMP,
	constraint JOB_INST_EXEC_FK foreign key (JOB_INSTANCE_ID)
	references BATCH_JOB_INSTANCE(JOB_INSTANCE_ID)
) ;

CREATE TABLE BATCH_JOB_EXECUTION_PARAMS (
	JOB_EXECUTION_ID BIGINT NOT NULL,
	PARAMETER_NAME VARCHAR(100) NOT NULL,
	PARAMETER_TYPE VARCHAR(100) NOT NULL,
	PARAMETER_VALUE VARCHAR(2500),
	IDENTIFYING CHAR(1) NOT NULL,
	constraint JOB_EXEC_PARAMS_FK foreign key (JOB_EXECUTION_ID)
```

## 7. 테스트 `CatalogMigrationTest.java` (전체)

기존 `IntegrationTestSupport`를 상속하므로 Testcontainers(PostgreSQL 17.6)가 뜨고 Flyway가 V1~V4를 적용한 DB로 검사한다. `@Transactional`이라 테스트마다 롤백된다. PostgreSQL은 문장 하나가 실패하면 그 트랜잭션을 더 쓸 수 없어서, 거부를 확인하는 테스트는 실패하는 문장을 하나만 둔다.

```java
package com.ottnavi.migration;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatThrownBy;

import com.ottnavi.support.IntegrationTestSupport;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.dao.DataIntegrityViolationException;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.transaction.annotation.Transactional;

/**
 * V2~V4 마이그레이션 테스트(Task 033): 시드가 들어가고, 정상 데이터는 통과하며, 잘못된 데이터는 DB가 거부한다.
 * 클래스에 @Transactional을 붙여 테스트마다 롤백한다. PostgreSQL은 문장이 실패하면 그 트랜잭션을 더 쓸 수 없으므로
 * 거부를 확인하는 테스트는 실패하는 문장을 하나만 둔다.
 */
@Transactional
class CatalogMigrationTest extends IntegrationTestSupport {

    @Autowired
    JdbcTemplate jdbc;

    // 작품 한 건을 넣고 내부 id를 돌려준다
    private long insertTitle(String mediaType, int tmdbId) {
        return jdbc.queryForObject(
                "INSERT INTO title (media_type, tmdb_id, title, fetched_at) VALUES (?, ?, '테스트 작품', now()) RETURNING id",
                Long.class, mediaType, tmdbId);
    }

    // 시청 단위 한 건을 넣고 내부 id를 돌려준다. 영화면 seasonNumber를 null로 넘긴다
    private long insertWatchUnit(long titleId, String unitType, Integer seasonNumber) {
        return jdbc.queryForObject(
                "INSERT INTO watch_unit (title_id, unit_type, season_number, total_runtime_min, fetched_at) "
                        + "VALUES (?, ?, ?, 120, now()) RETURNING id",
                Long.class, titleId, unitType, seasonNumber);
    }

    @Test
    void 제공처_시드_8행이_모두_서비스에_연결돼_있다() {
        Integer mapped = jdbc.queryForObject(
                "SELECT count(*) FROM tmdb_provider WHERE mapping_state = 'MAPPED' AND ott_service_id IS NOT NULL",
                Integer.class);
        String adTier = jdbc.queryForObject("SELECT tier FROM tmdb_provider WHERE provider_id = 1796", String.class);

        assertThat(mapped).isEqualTo(8);
        assertThat(adTier).isEqualTo("AD");
    }

    @Test
    void 영화와_드라마는_같은_TMDB_ID를_쓸_수_있다() {
        insertTitle("MOVIE", 1000);
        insertTitle("TV", 1000);

        Integer count = jdbc.queryForObject("SELECT count(*) FROM title WHERE tmdb_id = 1000", Integer.class);
        assertThat(count).isEqualTo(2);
    }

    @Test
    void 같은_종류_같은_TMDB_ID는_거부한다() {
        insertTitle("MOVIE", 1001);

        assertThatThrownBy(() -> insertTitle("MOVIE", 1001)).isInstanceOf(DataIntegrityViolationException.class);
    }

    @Test
    void 영화_시청단위는_시즌이_NULL이어도_작품당_하나만_허용한다() {
        long titleId = insertTitle("MOVIE", 1002);
        insertWatchUnit(titleId, "MOVIE", null);

        assertThatThrownBy(() -> insertWatchUnit(titleId, "MOVIE", null))
                .isInstanceOf(DataIntegrityViolationException.class);
    }

    @Test
    void 시즌인데_시즌_번호가_없으면_거부한다() {
        long titleId = insertTitle("TV", 1003);

        assertThatThrownBy(() -> insertWatchUnit(titleId, "SEASON", null))
                .isInstanceOf(DataIntegrityViolationException.class);
    }

    @Test
    void 모름_상태에_이유가_없으면_거부한다() {
        long unitId = insertWatchUnit(insertTitle("MOVIE", 1004), "MOVIE", null);

        assertThatThrownBy(() -> jdbc.update(
                "INSERT INTO availability (watch_unit_id, ott_service_id, status, checked_at) VALUES (?, 1, 'UNKNOWN', now())",
                unitId)).isInstanceOf(DataIntegrityViolationException.class);
    }

    @Test
    void 모름_상태에_이유가_있으면_저장된다() {
        long unitId = insertWatchUnit(insertTitle("MOVIE", 1005), "MOVIE", null);

        int rows = jdbc.update(
                "INSERT INTO availability (watch_unit_id, ott_service_id, status, unknown_reason, checked_at) "
                        + "VALUES (?, 7, 'UNKNOWN', 'STRUCTURAL_GAP', now())",
                unitId);
        assertThat(rows).isEqualTo(1);
    }

    @Test
    void 매핑됨_상태인데_서비스가_없으면_거부한다() {
        assertThatThrownBy(() -> jdbc.update(
                "INSERT INTO tmdb_provider (provider_id, tmdb_name, mapping_state) VALUES (99999, '테스트', 'MAPPED')"))
                .isInstanceOf(DataIntegrityViolationException.class);
    }

    @Test
    void 같은_상품의_같은_시작일_요금은_거부한다() {
        long productId = jdbc.queryForObject(
                "INSERT INTO subscription_product (name, product_type) VALUES ('테스트 상품', 'SINGLE') RETURNING id",
                Long.class);
        String sql = "INSERT INTO product_price (product_id, monthly_price, effective_from, last_verified_at) "
                + "VALUES (?, 13500, DATE '2026-10-01', now())";
        jdbc.update(sql, productId);

        assertThatThrownBy(() -> jdbc.update(sql, productId)).isInstanceOf(DataIntegrityViolationException.class);
    }

    @Test
    void 시청단위가_참조하는_작품은_지울_수_없다() {
        long titleId = insertTitle("MOVIE", 1006);
        insertWatchUnit(titleId, "MOVIE", null);

        assertThatThrownBy(() -> jdbc.update("DELETE FROM title WHERE id = ?", titleId))
                .isInstanceOf(DataIntegrityViolationException.class);
    }

    @Test
    void 변경_이력은_실행_ID_인덱스를_갖는다() {
        Integer indexes = jdbc.queryForObject(
                "SELECT count(*) FROM pg_indexes WHERE indexname = 'idx_availability_change_job'", Integer.class);
        assertThat(indexes).isEqualTo(1);
    }

    @Test
    void Spring_Batch_메타_테이블_6개가_만들어져_있다() {
        Integer tables = jdbc.queryForObject(
                "SELECT count(*) FROM information_schema.tables WHERE table_schema = 'public' AND table_name LIKE 'batch_%'",
                Integer.class);
        assertThat(tables).isEqualTo(6);
    }
}
```

## 9. ERD와 SQL에서 어긋난 점, 확인한 것과 못 한 것

**ERD와 맞춘 것:** ERD 머리말은 "표시가 없는 컬럼은 `NOT NULL`"이라고 정한다. 이 안내서를 쓰면서 NULL이 될 수 있는 컬럼(`title.overview`·`release_date`·`poster_path` 등, `watch_unit.season_number`·`name`·`air_date`, `title_cast.character_name`·`profile_path`, `tmdb_provider.logo_path`, `availability_change.before_status`, `plan.activated_at`·`change_summary`, `plan_item.reason`·`completed_month_index`, `notification_outbox.sent_at`·`last_error` 등)에 표시가 빠져 있어 같은 PR에서 `ERD.md`에 `NULL 허용`/`NULL` 표시를 보강했다. 위 SQL의 NOT NULL 여부는 이제 ERD와 같다. 다만 `users`의 컬럼은 근거 문서가 없어 모두 `NOT NULL`로 두었으니 Task 034에서 구글 로그인 응답에 맞춰 확인한다.

**확인한 것(`실행 확인`):** V1~V4 적용, 시드 8행(전부 MAPPED, 1796은 AD), 정상 입력 통과, 거부 13건, `job_execution_id` 인덱스 사용(`enable_seqscan=off`로 확인), `BATCH_*` 6개·시퀀스 3개, Gradle 테스트 전체 441건 실패 0.

**확인 못 한 것:** Supabase(17.11)와 Cloudtype 배포 환경에서 적용, 엔티티와의 `validate`(Task 035), 수만 건 규모의 성능, 고도화 후보 인덱스(`title_cast`, `title_genre` 역방향 조회)는 만들지 않았다(필요해지면 새 마이그레이션).
