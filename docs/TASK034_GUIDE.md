> 2026-10-13 작성. 기준은 `docs/ERD.md` v0.4(C·D·E 영역), `docs/ROADMAP.md` Task 034, ROADMAP Task 032 `기록:`의 확정 결정(D1~D9)이다.

## 2. 동작 흐름

앱이 뜨면 Flyway가 `V1 → … → V7` 순서로 아직 안 적용된 파일만 실행한다(`docs/FLYWAY_GUIDE.md` 2절). V5가 `users`를 만들면 V5의 나머지 표와 V6·V7이 `users`를 가리키는 FK를 걸 수 있다.

**삭제 흐름이 이 Task의 핵심이다.** FK `ON DELETE`로 DB가 하위 행을 지운다(JPA cascade 삭제는 쓰지 않는다, TECH T-1).

```
users 1행 삭제(탈퇴)
 ├─ CASCADE → user_setting, user_subscription, user_price_override, wishlist_item, notification_outbox
 └─ CASCADE → plan ─ CASCADE → plan_month ─ CASCADE → plan_month_product
                  │                      └─ CASCADE → plan_assignment
                  └─ CASCADE → plan_item ── CASCADE → plan_assignment
plan 삭제 시 calc_run.plan_id, plan.previous_plan_id는 SET NULL(행은 남는다)
```

DB가 막아 주는 잘못된 데이터는 이렇다. 테스트와 대응한다.

| 제약 | 막는 것 |
|---|---|
| `uk_plan_active` (부분 유니크) | 한 사용자의 ACTIVE 플랜 2개 |
| `uk_plan_draft_type` (부분 유니크) | 같은 유형 DRAFT 2개(다른 유형 DRAFT 3개는 허용) |
| `ck_plan_activated` | DRAFT인데 `activated_at`이 있음 / ACTIVE·ARCHIVED인데 없음 |
| `ck_plan_month_confirmed` | `confirmed`가 `month_index = 0`과 다름 |
| `ck_plan_item_reason` | UNSCHEDULED인데 이유 없음 / SCHEDULED인데 이유 있음 |
| `ck_user_subscription_paid_only` | 구독 중이 아닌데 요금제 이름·결제일이 있음 |
| `uk_notification_outbox_dedupe` | 같은 `dedupe_key` 알림 중복 생성 |

## 3. 파일 ① `V5__create_user.sql` (전체)

```sql
-- V5: 사용자 영역(ERD C). users, user_setting, user_subscription, user_price_override, wishlist_item (Task 034)
-- 탈퇴(FR-07)하면 users 행 하나를 지워 이 영역과 D·E 영역의 사용자 행이 함께 사라진다(FK ON DELETE CASCADE, TECH T-1).
-- NULL 표기가 없는 컬럼은 NOT NULL이다(ERD 머리말).

-- 로그인 사용자. 테이블 이름은 예약어(user)를 피하려고 복수형이다
CREATE TABLE users (
	id             BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	email          VARCHAR(255) NOT NULL,
	name           VARCHAR(100) NOT NULL,                         -- 구글 표시 이름. 비어 오면 서비스가 이메일 앞부분으로 채운다
	role           VARCHAR(10)  NOT NULL DEFAULT 'USER',          -- USER / ADMIN
	oauth_provider VARCHAR(20)  NOT NULL,                         -- MVP는 GOOGLE만
	oauth_subject  VARCHAR(100) NOT NULL,                         -- 구글 계정의 고유 번호(sub)
	created_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
	updated_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
	CONSTRAINT uk_users_email UNIQUE (email),
	CONSTRAINT uk_users_oauth UNIQUE (oauth_provider, oauth_subject),
	CONSTRAINT ck_users_role CHECK (role IN ('USER', 'ADMIN')),
	CONSTRAINT ck_users_oauth_provider CHECK (oauth_provider IN ('GOOGLE'))
);

-- 계산 조건. 행이 있으면 온보딩을 마친 사용자이고, 행은 첫 설정 저장(PUT /me/settings)이 만든다(가입 때 만들지 않는다)
CREATE TABLE user_setting (
	user_id               BIGINT      PRIMARY KEY REFERENCES users (id) ON DELETE CASCADE,   -- 탈퇴 시 함께 삭제
	monthly_budget        INT         NOT NULL,
	monthly_watch_minutes INT         NOT NULL,
	watch_preset          VARCHAR(10) NOT NULL,                   -- LIGHT / NORMAL / HEAVY / CUSTOM
	notification_enabled  BOOLEAN     NOT NULL DEFAULT FALSE,     -- 알림은 기본 꺼짐(D6)
	created_at            TIMESTAMPTZ NOT NULL DEFAULT now(),
	updated_at            TIMESTAMPTZ NOT NULL DEFAULT now(),
	CONSTRAINT ck_user_setting_budget CHECK (monthly_budget >= 0),
	CONSTRAINT ck_user_setting_minutes CHECK (monthly_watch_minutes >= 0),
	CONSTRAINT ck_user_setting_preset CHECK (watch_preset IN ('LIGHT', 'NORMAL', 'HEAVY', 'CUSTOM'))
);

-- 서비스별 이용 상태. 미구독은 행을 두지 않는다(API가 행 없는 서비스를 NOT_SUBSCRIBED로 채운다)
CREATE TABLE user_subscription (
	id             BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	user_id        BIGINT      NOT NULL REFERENCES users (id) ON DELETE CASCADE,             -- 탈퇴 시 함께 삭제
	ott_service_id BIGINT      NOT NULL REFERENCES ott_service (id),
	status         VARCHAR(20) NOT NULL,                          -- SUBSCRIBED / FREE / UNKNOWN
	product_id     BIGINT      REFERENCES subscription_product (id),                         -- MVP는 NULL. 계산 단계가 서비스의 판매 중 단품을 찾는다
	plan_name      VARCHAR(30),                                   -- 표시용 요금제 이름. SUBSCRIBED일 때만 값이 있다
	billing_day    INT,                                           -- 결제일 1~31. SUBSCRIBED일 때만 값이 있다. 비면 서비스가 1을 채운다(DB 기본값 없음, D5)
	created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
	updated_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
	CONSTRAINT uk_user_subscription_user_service UNIQUE (user_id, ott_service_id),
	CONSTRAINT ck_user_subscription_status CHECK (status IN ('SUBSCRIBED', 'FREE', 'UNKNOWN')),
	CONSTRAINT ck_user_subscription_billing_day CHECK (billing_day IS NULL OR billing_day BETWEEN 1 AND 31),
	CONSTRAINT ck_user_subscription_paid_only CHECK (status = 'SUBSCRIBED' OR (plan_name IS NULL AND billing_day IS NULL))
);

-- 관리자 가격을 바꾸지 않고 사용자별로 덮어쓰는 금액(FR-11)
CREATE TABLE user_price_override (
	id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	user_id       BIGINT      NOT NULL REFERENCES users (id) ON DELETE CASCADE,              -- 탈퇴 시 함께 삭제
	product_id    BIGINT      NOT NULL REFERENCES subscription_product (id),
	monthly_price INT         NOT NULL,
	created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
	updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
	CONSTRAINT uk_user_price_override_user_product UNIQUE (user_id, product_id),
	CONSTRAINT ck_user_price_override_price CHECK (monthly_price >= 0)
);

-- 찜. 드라마는 시즌별 행으로 저장한다. watched_at이 있으면 계산에서 제외한다.
-- 사용자당 최대 20개(watched_at이 없는 행)는 DB 제약이 아니라 서비스 규칙이다(Task 056에서 동시 요청 직렬화)
CREATE TABLE wishlist_item (
	id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	user_id       BIGINT      NOT NULL REFERENCES users (id) ON DELETE CASCADE,              -- 탈퇴 시 함께 삭제
	watch_unit_id BIGINT      NOT NULL REFERENCES watch_unit (id),
	priority      VARCHAR(10) NOT NULL,                           -- MUST / WANT / MAYBE
	watched_at    TIMESTAMPTZ,                                    -- 다 봤음 표시 시각
	created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
	updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
	CONSTRAINT uk_wishlist_item_user_unit UNIQUE (user_id, watch_unit_id),
	CONSTRAINT ck_wishlist_item_priority CHECK (priority IN ('MUST', 'WANT', 'MAYBE'))
);
```

## 4. 파일 ② `V6__create_plan.sql` (전체)

```sql
-- V6: 플랜 영역(ERD D). plan, plan_month, plan_month_product, plan_item, plan_assignment, calc_run (Task 034)
-- 계산 결과는 그 시점의 가격·조건을 복사한 스냅샷이다. DRAFT를 지우거나 사용자가 탈퇴하면 하위 행이 FK CASCADE로 함께 사라진다.
-- JPA는 cascade 삭제를 쓰지 않는다. plan 삭제는 벌크 JPQL로 하고 하위 행은 DB가 지운다(TECH T-1).

CREATE TABLE plan (
	id                    BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	user_id               BIGINT       NOT NULL REFERENCES users (id) ON DELETE CASCADE,     -- 탈퇴 시 함께 삭제
	previous_plan_id      BIGINT       REFERENCES plan (id) ON DELETE SET NULL,              -- 재계산 전 플랜. 지워져도 이 플랜은 남긴다(자기참조 삭제 순서 문제 방지)
	status                VARCHAR(10)  NOT NULL,                  -- DRAFT / ACTIVE / ARCHIVED
	plan_type             VARCHAR(15)  NOT NULL,                  -- RECOMMENDED / SAVER / SIMPLE
	start_month           DATE         NOT NULL,                  -- 첫 달의 1일. API에서는 YYYY-MM
	monthly_budget        INT          NOT NULL,                  -- 계산 당시 값의 스냅샷
	monthly_watch_minutes INT          NOT NULL,                  -- 계산 당시 값의 스냅샷
	algorithm             VARCHAR(10)  NOT NULL,                  -- EXACT / GREEDY
	must_total            INT          NOT NULL,
	must_completed        INT          NOT NULL,
	score                 INT          NOT NULL,
	total_cost            INT          NOT NULL,
	all_subscribe_cost    INT          NOT NULL,                  -- 절감액 = all_subscribe_cost - total_cost (절감액은 저장하지 않는다)
	data_as_of            TIMESTAMPTZ  NOT NULL,                  -- 계산에 쓴 마지막 완료 수집 시각(D2)
	activated_at          TIMESTAMPTZ,                            -- ACTIVE로 저장된 시각. DRAFT만 NULL(D1)
	change_summary        TEXT,                                   -- 재계산 변경 요약. MVP는 NULL, 형식은 Task 069에서 정한다
	created_at            TIMESTAMPTZ  NOT NULL DEFAULT now(),
	updated_at            TIMESTAMPTZ  NOT NULL DEFAULT now(),
	CONSTRAINT ck_plan_status CHECK (status IN ('DRAFT', 'ACTIVE', 'ARCHIVED')),
	CONSTRAINT ck_plan_type CHECK (plan_type IN ('RECOMMENDED', 'SAVER', 'SIMPLE')),
	CONSTRAINT ck_plan_algorithm CHECK (algorithm IN ('EXACT', 'GREEDY')),
	CONSTRAINT ck_plan_activated CHECK ((status = 'DRAFT') = (activated_at IS NULL)),
	CONSTRAINT ck_plan_must CHECK (must_completed <= must_total),
	CONSTRAINT ck_plan_start_month CHECK (EXTRACT(DAY FROM start_month) = 1),
	CONSTRAINT ck_plan_amounts CHECK (monthly_budget >= 0 AND monthly_watch_minutes >= 0 AND must_total >= 0
		AND must_completed >= 0 AND score >= 0 AND total_cost >= 0 AND all_subscribe_cost >= 0)
);
-- 사용자당 ACTIVE는 하나, DRAFT는 유형마다 하나. 부분 유니크 인덱스(WHERE 조건에 맞는 행끼리만 유일해야 한다)
CREATE UNIQUE INDEX uk_plan_active ON plan (user_id) WHERE status = 'ACTIVE';
CREATE UNIQUE INDEX uk_plan_draft_type ON plan (user_id, plan_type) WHERE status = 'DRAFT';
-- 위 두 인덱스는 ARCHIVED 행을 덮지 못하므로 사용자 삭제(탈퇴)용 인덱스를 따로 둔다
CREATE INDEX idx_plan_user ON plan (user_id);
CREATE INDEX idx_plan_previous ON plan (previous_plan_id);

CREATE TABLE plan_month (
	id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	plan_id     BIGINT      NOT NULL REFERENCES plan (id) ON DELETE CASCADE,                 -- 플랜 삭제 시 함께 삭제
	month_index INT         NOT NULL,                             -- 0은 확정(이번 달), 1·2는 예상
	month       DATE        NOT NULL,                             -- 그 달의 1일. API에서는 YYYY-MM
	confirmed   BOOLEAN     NOT NULL,                             -- month_index가 0이면 true(파생 값이라 CHECK로 묶는다)
	cost        INT         NOT NULL,
	CONSTRAINT uk_plan_month_plan_index UNIQUE (plan_id, month_index),
	CONSTRAINT ck_plan_month_index CHECK (month_index >= 0),
	CONSTRAINT ck_plan_month_confirmed CHECK (confirmed = (month_index = 0)),
	CONSTRAINT ck_plan_month_first_day CHECK (EXTRACT(DAY FROM month) = 1),
	CONSTRAINT ck_plan_month_cost CHECK (cost >= 0)
);

-- 그 달에 구독할 상품. 가격 스냅샷이라 이후 가격이 바뀌어도 변하지 않는다
CREATE TABLE plan_month_product (
	id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	plan_month_id BIGINT      NOT NULL REFERENCES plan_month (id) ON DELETE CASCADE,         -- 달 삭제 시 함께 삭제
	product_id    BIGINT      NOT NULL REFERENCES subscription_product (id),
	applied_price INT         NOT NULL,
	price_source  VARCHAR(20) NOT NULL,                           -- ADMIN / USER_OVERRIDE / ALREADY_PAID / FREE
	CONSTRAINT uk_plan_month_product UNIQUE (plan_month_id, product_id),                     -- plan_month_id 조회도 이 인덱스가 맡는다
	CONSTRAINT ck_plan_month_product_price CHECK (applied_price >= 0),
	CONSTRAINT ck_plan_month_product_source CHECK (price_source IN ('ADMIN', 'USER_OVERRIDE', 'ALREADY_PAID', 'FREE'))
);

-- 찜 단위(작품 또는 시즌) 결과. "남은 작품과 이유"(FR-12)의 원천
CREATE TABLE plan_item (
	id                    BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	plan_id               BIGINT      NOT NULL REFERENCES plan (id) ON DELETE CASCADE,       -- 플랜 삭제 시 함께 삭제
	watch_unit_id         BIGINT      NOT NULL REFERENCES watch_unit (id),
	priority              VARCHAR(10) NOT NULL,                   -- MUST / WANT / MAYBE (계산 당시 스냅샷)
	outcome               VARCHAR(15) NOT NULL,                   -- SCHEDULED / UNSCHEDULED
	reason                VARCHAR(15),                            -- UNSCHEDULED일 때만: NO_PROVIDER / UNKNOWN / BUDGET / TIME
	completed_month_index INT,                                    -- 시청을 끝내는 달(month_index). UNSCHEDULED면 NULL
	CONSTRAINT uk_plan_item_plan_unit UNIQUE (plan_id, watch_unit_id),
	CONSTRAINT ck_plan_item_priority CHECK (priority IN ('MUST', 'WANT', 'MAYBE')),
	CONSTRAINT ck_plan_item_outcome CHECK (outcome IN ('SCHEDULED', 'UNSCHEDULED')),
	CONSTRAINT ck_plan_item_reason CHECK ((outcome = 'UNSCHEDULED') = (reason IS NOT NULL)),
	CONSTRAINT ck_plan_item_reason_value CHECK (reason IS NULL OR reason IN ('NO_PROVIDER', 'UNKNOWN', 'BUDGET', 'TIME')),
	CONSTRAINT ck_plan_item_completed CHECK (completed_month_index IS NULL
		OR (outcome = 'SCHEDULED' AND completed_month_index >= 0))
);

-- 월별 시청 배정. 긴 시즌은 연속된 달에 걸쳐 여러 행으로 나뉘고 한 달에 한 조각이다
CREATE TABLE plan_assignment (
	id             BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	plan_item_id   BIGINT NOT NULL REFERENCES plan_item (id) ON DELETE CASCADE,              -- 항목 삭제 시 함께 삭제
	plan_month_id  BIGINT NOT NULL REFERENCES plan_month (id) ON DELETE CASCADE,             -- 달 삭제 시 함께 삭제(두 경로 모두 CASCADE)
	ott_service_id BIGINT NOT NULL REFERENCES ott_service (id),
	minutes        INT    NOT NULL,
	CONSTRAINT uk_plan_assignment_item_month UNIQUE (plan_item_id, plan_month_id),
	CONSTRAINT ck_plan_assignment_minutes CHECK (minutes > 0)
);
CREATE INDEX idx_plan_assignment_month ON plan_assignment (plan_month_id);

-- 완전탐색·그리디 비교 기록(FR-13). 플랜이 지워져도 통계로 남기고 plan_id만 NULL로 바꾼다
CREATE TABLE calc_run (
	id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	plan_id         BIGINT      REFERENCES plan (id) ON DELETE SET NULL,
	input_hash      CHAR(64)    NOT NULL,                         -- 정규화한 입력의 SHA-256(16진수 64자)
	plan_type       VARCHAR(15) NOT NULL,
	algorithm       VARCHAR(10) NOT NULL,
	must_completed  INT         NOT NULL,
	score           INT         NOT NULL,
	total_cost      INT         NOT NULL,
	candidate_count INT         NOT NULL,
	elapsed_ms      BIGINT      NOT NULL,
	created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
	CONSTRAINT ck_calc_run_type CHECK (plan_type IN ('RECOMMENDED', 'SAVER', 'SIMPLE')),
	CONSTRAINT ck_calc_run_algorithm CHECK (algorithm IN ('EXACT', 'GREEDY')),
	CONSTRAINT ck_calc_run_numbers CHECK (must_completed >= 0 AND score >= 0 AND total_cost >= 0
		AND candidate_count >= 0 AND elapsed_ms >= 0)
);
CREATE INDEX idx_calc_run_plan ON calc_run (plan_id);
```

## 5. 파일 ③ `V7__create_notification.sql` (전체)

`shedlock` 구조는 ShedLock 공식 PostgreSQL 스크립트와 같다(이름·타입을 바꾸면 라이브러리가 동작하지 않는다). 발송 기본 방식은 `usingDbTime()`이라 시각 비교를 DB 시계로 한다(TECH 5절).

```sql
-- V7: 알림·운영 영역(ERD E). notification_outbox, shedlock (Task 034)
-- BATCH_* 테이블은 V4에서 만들었다.

-- 보낼 메일을 먼저 이 표에 적고(outbox) 별도 작업이 발송한다. 발송 이력 조회(FR-16)도 이 표를 쓴다
CREATE TABLE notification_outbox (
	id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
	user_id         BIGINT       NOT NULL REFERENCES users (id) ON DELETE CASCADE,           -- 탈퇴 시 함께 삭제
	type            VARCHAR(20)  NOT NULL,                        -- SUBSCRIBE_GUIDE / MONTHLY / PLAN_CHANGE
	dedupe_key      VARCHAR(100) NOT NULL,                        -- 중복 생성 방지. 예: MONTHLY:{userId}:2026-11
	payload         JSONB        NOT NULL,                        -- 메일 본문을 만들 재료
	status          VARCHAR(10)  NOT NULL DEFAULT 'PENDING',      -- PENDING / SENT / FAILED
	attempt_count   INT          NOT NULL DEFAULT 0,
	next_attempt_at TIMESTAMPTZ  NOT NULL DEFAULT now(),          -- 이 시각 이후에 발송을 시도한다
	sent_at         TIMESTAMPTZ,
	last_error      TEXT,
	created_at      TIMESTAMPTZ  NOT NULL DEFAULT now(),
	updated_at      TIMESTAMPTZ  NOT NULL DEFAULT now(),
	CONSTRAINT uk_notification_outbox_dedupe UNIQUE (dedupe_key),
	CONSTRAINT ck_notification_outbox_type CHECK (type IN ('SUBSCRIBE_GUIDE', 'MONTHLY', 'PLAN_CHANGE')),
	CONSTRAINT ck_notification_outbox_status CHECK (status IN ('PENDING', 'SENT', 'FAILED')),
	CONSTRAINT ck_notification_outbox_attempt CHECK (attempt_count >= 0)
);
CREATE INDEX idx_notification_outbox_due ON notification_outbox (status, next_attempt_at);   -- 발송 대상 조회
CREATE INDEX idx_notification_outbox_user ON notification_outbox (user_id);                  -- 탈퇴 삭제용

-- @Scheduled 작업의 중복 실행을 막는 ShedLock 락 표. 구조는 ShedLock 공식 PostgreSQL 스크립트 그대로이며 이름·타입을 바꾸지 않는다
CREATE TABLE shedlock (
	name       VARCHAR(64)  NOT NULL,
	lock_until TIMESTAMP    NOT NULL,
	locked_at  TIMESTAMP    NOT NULL,
	locked_by  VARCHAR(255) NOT NULL,
	PRIMARY KEY (name)
);
```

## 9. ERD와 SQL에서 정한 점, 확인한 것과 못 한 것

**이 안내서가 정한 것(ERD가 "034에서 확정"으로 남긴 것):**
- `users`는 `email`·`name`·`oauth_provider`·`oauth_subject` 모두 `NOT NULL`. 구글 이름이 비어 오면 서비스가 이메일 앞부분으로 채운다. 틀렸으면 새 마이그레이션이 아니라 이 안내서를 고쳐 병합 전에 반영한다(`oauth_provider`는 `GOOGLE`만 허용하는 CHECK).
- `plan_item.completed_month_index`는 NULL 허용이고 SCHEDULED일 때만 값이 있을 수 있다(UNSCHEDULED면 NULL, `>= 0`). SCHEDULED에 반드시 값이 있어야 하는지는 Task 063·064에서 정한 뒤 필요하면 CHECK를 더한다.
- `plan.change_summary`는 `TEXT`다. 형식(문장인지 JSON인지)은 Task 069에서 정하고, 바꾸려면 새 마이그레이션을 추가한다.
- `calc_run.input_hash`는 `CHAR(64)`(SHA-256 16진수 문자열).
- ROADMAP Task 034 구현 사항의 추가 인덱스 목록에 `plan_month_product(plan_month_id)`가 있지만 ERD 규칙(유니크 인덱스 선두 컬럼이 덮는 FK는 따로 만들지 않는다)에 따라 **만들지 않았다**. `UNIQUE(plan_month_id, product_id)`가 그 역할을 한다. 같은 PR에서 ROADMAP 문구도 고친다.
- 열거 값(`status`, `plan_type`, `price_source` 등)과 금액·분 `>= 0` 하한 CHECK를 넣었다(Task 032 D3). 입력 상·하한(120~44640분, 100만 원)은 계약 검증에 맡겼다.

**확인한 것(`실행 확인`):** V5~V7 적용, 정상 입력 통과, 거부 14건(유니크·CHECK 위반), DRAFT 삭제 CASCADE(하위 4개 표 0행), 사용자 삭제 CASCADE와 `calc_run.plan_id` NULL, 인덱스 존재, Gradle 테스트 11건 통과(V1~V7).

**확인 못 한 것:** 033 병합 전이라 실제 V2~V4 파일이 아니라 033 안내서의 SQL로 확인했다. Supabase(17.11)·Cloudtype 배포 환경에서 적용, 엔티티와의 `validate`(Task 035·062), 백엔드 전체 테스트.
