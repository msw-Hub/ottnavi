  - TMDB에서 받은 정보는 **6개월 안에 갱신·삭제**해야 한다. PRD FR-18(6개월 기준)과 일치하므로 설계 변경은 없다.

## 2. 7개 서비스 해지 예약 정책 (R11-27)

### 서비스별 원문 근거

- **넷플릭스**: "결제 주기가 남아 있을 때 해지하면 결제 주기가 종료되어 계정이 자동으로 해지될 때까지 넷플릭스를 이용할 수 있습니다." 계정에 해지 옵션이 없으면 결제 파트너를 통해 해지해야 한다. "예약 해지"라는 표현은 원문에 없고 의미만 같다. 환불 문구는 이 페이지에 없다.
- **디즈니+**: 사용자가 이용 약관 2절(구독 조건) c항 원문을 복사해 제공했다(2026-10-05, 시행일은 이번 원문에 없음). 앞서 확인한 "[이전] 취소 및 환불 정책" 페이지와 같은 내용이다. **취소**: "달리 공지되지 않는 한 결제의 자동갱신을 중단하여 해당 결제 주기의 종료 시점에 발효될 것이고, 이 경우 귀하는 그 시점까지는 계속해서 디즈니+ 서비스를 이용할 수 있습니다." 무료 체험·프로모션 코드로 구독한 경우 취소는 즉시 발효될 수 있다. 취소 신청일부터 결제 주기 종료까지의 기간은 환불되지 않는다. **즉시 취소·잔여기간 환불**은 고객센터(온라인 채팅·전화)로 요청하며, 해당 결제 주기에 시청 이력이 없으면 위약금 없이, 시청 이력이 있으면 정상 구독료의 **최대 10% 위약금**(부대비용·결제대행수수료 포함)을 차감한다. 환불액은 할인 전 정상 월간 구독료 기준으로 사용 기간을 비례 공제해 산정하고, 즉시 취소하면 요청일부터 이용할 수 없다. **7일 청약철회**: 결제일로부터 7일 이내이고 콘텐츠를 시청하지 않은 경우만 가능하며, 접속·시청을 시작했거나 7일이 지나면 권리를 상실한다. **제3자 결제**(앱스토어·제3자 구독 사이트)는 청약철회 정책을 포함해 제3자의 정책이 적용되고 디즈니+의 정책은 적용되지 않는다.
  - **주의**: 확인한 페이지가 "[이전] 취소 및 환불 정책 - 대한민국"이고 시행일 2025-05-16, 기존 가입자 적용일 2025-06-24다. 현재 유효한 정책 페이지가 따로 있을 수 있다.
- **Apple TV+**: 사용자가 약관 전문과 구독 취소 안내 원문을 복사해 제공했다(2026-10-05). **약관 I절(구독)**: 구독은 계정 설정의 구독 관리에서 취소하지 않으면 자동 갱신된다. 환불은 구독 구입 후 역일로 7일 이내에 이메일 양식으로 받을 수 있고(이미 수신한 구독 콘텐츠는 일할 계산) 그 외에는 환불·반환·취소가 안 된다. 무료 체험이 종료되기 최소 24시간 전에 취소해야 요금이 청구되지 않는다. 서비스 구독이 종료되면 구독이 필요한 기능·콘텐츠를 이용할 수 없다. **취소 안내(118428)**: "구독 취소" 버튼이 없거나 **만료 메시지가 빨간색 텍스트로 표시되면 구독이 이미 취소된 것**이다. 즉 "취소 후 현재 청구 기간이 끝날 때까지 이용할 수 있다"는 문장은 약관·안내 어디에도 **명문으로 없고**, 취소 후에도 구독 관리 화면에 만료일이 표시되는 구조로만 알 수 있다. 안내 문구는 "취소 후 이용 종료일은 Apple 구독 관리 화면에 표시되는 만료일을 확인하세요"로 쓴다.
- **티빙**: 사용자가 유료이용약관 전문을 복사해 제공했다(2026-10-05, 2026-08-03 시행). 처음 요약의 "제16·17조"는 틀린 번호였고, 해지는 **제8조(정기결제 상품)·제12~15조(제4장)** 에 있다. **제8조 제3항**: "정기결제 상품의 해지를 신청한 경우 이미 결제된 이용기간 만료일까지 유료서비스를 이용할 수 있고, 다음 결제주기부터 자동결제가 이루어지지 않습니다. 이용기간 중 해지는 제13조에 따릅니다." 제8조 제2항: 회사가 결제 전에 결제 예정 내역·결제 예정일·해지 방법을 전자적 수단으로 안내한다("결제 예정일 전일까지 해지해야 한다"는 문구는 약관에 **없고**, 서비스 화면 안내에 따른다). **제12조**: 수신확인통지를 받은 날부터 7일 이내 청약철회, 단 법령상 제한 사유나 **유료서비스 이용 개시** 등으로 철회가 제한될 수 있다(시청 이력이라는 표현은 약관에 없음). **제13조**: 이용기간 중 중도해지는 법령이 인정하거나 상품별 이용조건·화면에서 별도로 인정하는 경우에만. **제15조**: 청약철회는 실제 결제금액 전액 환불, 해지가 인정되면 실제 결제금액에서 기 이용금액(기 이용일수 × 정상 일일 이용대금, 할인 전 정상가 ÷ 총 이용가능일수)을 공제하고 환불대상금액의 **10%를 환불수수료로 공제**(회사 귀책이거나 제10조 제3항에 따른 환불은 공제 없음). **인앱결제(Apple·Google)·제휴 판매**는 각 사업자의 약관·정책을 따른다(제7조 제3항, 제12조 제7항, 제15조 제2항 라목).
- **웨이브**: 사용자 제공 링크 `help.wavve.com`도 **접속되지 않는다**. 결제 약관 확인 결과
  - 제8조 제3항: "자동결제를 해지하는 경우 다음 정기 결제 예정일로부터 청구 및 결제가 중단되어 서비스 이용기간 갱신이 중단됩니다." / "회원은 기 결제한 서비스를 잔존 이용기간에도 제한 없이 이용할 수 있습니다."

### 3.2 Supabase Free (사용자 제공 + 공식 문서 대조)

| 항목 | 한도 | 수준 | 비고 |
|---|---|---|---|
| DB 크기 | 프로젝트당 **500MB** | 확인됨 | 초과 시 읽기 전용. 포함: 데이터·인덱스·구체화된 뷰(디스크에는 WAL·Postgres 로그도 포함). 복구: SQL 편집기에서 `set session characteristics as transaction read write;` → 데이터 삭제 → `vacuum;` → `set default_transaction_read_only = 'off';` 또는 Pro 업그레이드 |
| 비활성 일시정지 | **7일** 동안 충분한 DB 활동이 없으면 정지 | 확인됨 | 활동 = 지난 한 주 동안 하루 몇 건의 사용자 DB 요청(API 호출·연결된 애플리케이션 요청). 정지 약 1주 전 경고 이메일. 정지 후 데이터·설정 유지, 대시보드 "Resume project"로 복구, **정지 후 최대 1년까지 복구 가능** |
| Egress | 미캐시 5GB + 캐시 5GB(독립 쿼터) | 확인됨 | 초과 시 알림·유예 기간, 이후 공정 이용 정책. **외부 서버(Cloudtype)가 받는 DB 결과가 포함되는지는 문서에 명시 없음(모름)** |
| Storage | 1GB | 사용자 제공 | DB와 별개 쿼터 |
| MAU / Third-Party MAU | 각 50,000 | 사용자 제공 | SSO는 Free에서 사용 불가 |
| Edge Functions | 500,000회/월 | 사용자 제공 | |
| Realtime | 메시지 2,000,000건/월, 동시 연결 200개 | 사용자 제공 | |

- 초과분은 자동 과금되지 않지만, 지속 초과 시 공정 이용 정책에 따른 제한이 있다(사용자 제공).
- **프로젝트 영향**
  - Supabase를 일반 PostgreSQL로만 쓰므로 MAU·Storage·Edge Functions·Realtime·SSO는 해당 없다. Data API는 사용자 판단으로 켜 둔 상태다(백엔드는 JDBC 직접 접속).
  - 가장 중요한 한도는 **DB 500MB**다. PRD 후보 규모는 약 5만 5천 건이고 TECH는 `BATCH_*` 이력 누적을 우려한다. **수집 구현 후 실제 크기를 측정**한다(`SELECT pg_size_pretty(pg_database_size(current_database()))`).
  - 7일 비활성은 Hobby 전환 후 매일 수집 cron이 막고, 무료 기간에는 대시보드에서 Resume한다(TECH 3절).
  - Supabase의 PostgreSQL 버전은 17.11이고 로컬 compose는 17.6이다. 17.x 마이너 차이라 호환에 문제가 없다고 보고 지금은 맞추지 않는다(맞출지는 사용자 결정).

### 3.3 Redis Cloud Free (공식 문서·지원 문서 원문으로 확인: 한도는 `redis.io`, 14일 비활성 삭제는 지원 문서 원문을 사용자가 복사해 제공)

| 월 네트워크 대역폭 | 5GB(플랜 전체가 공유) | **확인됨**(위와 동일) |
| 최대 처리량 | 100 ops/sec. 1KiB 요청 기준이고 실제 MB/s에 의해 상한이 정해진다(처리량 ÷ 1024가 MB/s 한도) | **확인됨**(위와 동일). TECH의 2차 자료 표기를 공식 근거로 바꿀 수 있다 |

| 비활성 삭제 방지 | 지원 문서는 각 Free DB에 **14일 안에 최소 한 번** Redis 명령을 실행하라고 안내한다. 예: `SET keepalive_key "active" EX 60`을 cron·스케줄러로 자동화 | **확인됨**(위와 동일, 14일 기준은 문서 내용) |

- `redis.io` 한도 표는 직접 조회로 확인했다. 지원 문서(`support.redislabs.com`)는 자동 조회가 두 번 모두 403으로 막혀, 사용자가 브라우저에서 원문을 복사해 제공했다(2026-10-05). 처음의 429는 사용자의 IP로 짧은 시간에 반복 접속해 걸린 것으로 보인다.
- **프로젝트 영향**
  - Redis에는 재생성 가능한 값(계산 캐시·요청 제한·Refresh Token)만 두므로 데이터 삭제는 손실이 아니라 번거로움이다. 백엔드의 Redis 사용은 늦게 시작하고(로컬 개발은 docker의 Redis), **14일 비활성 삭제는 확인된 정책**이라 DB를 만든 뒤 14일 안에 백엔드가 Redis 명령을 보내지 않으면 삭제된다. 삭제되면 엔드포인트·비밀번호가 바뀌어 Cloudtype 환경 변수를 다시 등록해야 한다.
  - 추가 주의: 지원 문서가 **"무료 DB는 운영 워크로드에 권장하지 않는다"** 고 하고, 삭제 정책이 "평가 서비스 이용약관"에 정의돼 있다. MVP 운영에 무료 DB를 쓰면 평가 용도 약관 아래에서 쓰는 셈이라 **사전 통지 없이 삭제될 수 있다**는 위험을 받아들이는 결정이다. 유료 Essentials(250MB부터)는 비활성으로 삭제되지 않는다. 유료 가격은 아직 조사하지 않았다.
  - 빈 구독 주의: Vercel·Heroku 연동으로 만든 Free DB가 삭제되면 빈 Free 구독이 남아 새 Free DB를 만들기 전에 그 구독을 먼저 삭제해야 할 수 있다(직접 만든 경우는 해당 없을 가능성이 크지만 확인하지 못함).
  - 대응 후보: ① 삭제되면 다시 만든다 ② Redis Cloud 생성을 MVP 배포 직전(Task 092 근처)으로 미룬다 ③ Keepalive를 자동화한다(`SET keepalive_key "active" EX 60`을 **매일 또는 매주** 실행하고 마지막 성공 시각을 감시해 14일 전에 경고한다. 접속 정보를 Actions에 두는 구성이 늘어난다) ④ 운영은 유료 Essentials로 간다(비용 조사 필요). Task 021 첫 배포에서 Redis가 필요한지(Task 016에서 `prod` 프로필의 Redis 헬스 체크를 끌지)에 따라 ①·②의 선택이 달라진다. 지금은 DB를 그대로 두고 **Task 020 환경 변수 등록 전에 DB가 살아 있는지 확인**한다.
  - 정한 설정: Eviction `allkeys-lru`, Persistence None, 버전 8.6. TLS는 현재 Off이고 Task 016·020에서 Spring 접속 확인과 함께 켤지 정한다.
  - TMDB 버킷을 로컬(인메모리)로 둔 결정(TECH 3절)은 100 ops/sec 한도 때문이며 그대로 유효하다.
