# 프로젝트를 만든 이유 (OTT내비)

> 2026-10-09 작성. 포트폴리오 소개, README, 자기소개서, 면접 답변에 쓸 **"왜 이 프로젝트를 만들었나"** 문구를 모아 둔 문서다.
> 아래 내용은 모두 사용자가 직접 겪은 경험이다. 새로 지어낸 사실을 넣지 않았고, 말투와 길이만 용도별로 다듬었다. 서비스 기능 설명은 `docs/PRD.md`가 기준이다.

## 1. 원문 (사용자가 쓴 그대로)

> OTT 종류는 많고, 각기 고유 컨텐츠 들이 있고, 또 한 OTT를 쭉 구독해보니 어느정도 보고나면 막상 땡기는 볼것도 없었다.
> 그래서 OTT구독을 어떻게하면 몰아보면서 뽕을 뽑으면서 볼 수 있을까? 라는 고민과, 넷플릭스에서 특정 컨텐츠(영화 등) 이름 검색해봐도 없어서, 어디 OTT에서 제공하는 지를 몰라 네이버나 구글에 검색하면서 찾는 경험을 통해서 이 사이트 제작을 결심했다.

원문에 담긴 이야기는 두 가지다.
1. **구독료를 비효율적으로 쓴 경험**: OTT마다 고유 콘텐츠가 있어 서비스가 많은데, 한 서비스를 계속 구독하니 어느 정도 보고 나면 더 보고 싶은 작품이 없었다. → "구독을 몰아서 보면서 본전을 뽑을 수 없을까?"
2. **작품이 어디에 있는지 찾기 어려웠던 경험**: 넷플릭스에서 영화를 검색했는데 없어서, 어느 OTT에 있는지 몰라 네이버와 구글을 오가며 직접 찾았다.

## 2. 다듬은 글

### 2.1 자기소개서·포트폴리오 소개용 (한 문단, 격식체)

국내에는 OTT 서비스가 많고, 서비스마다 고유한 콘텐츠가 있습니다. 하나의 OTT를 계속 구독해 보니, 어느 정도 시청하고 나면 더 보고 싶은 작품이 남아 있지 않은 경우가 많았습니다. 그래서 "여러 OTT의 구독을 어떻게 하면 효율적으로, 필요한 시기에 몰아서 보며 구독료만큼 충분히 이용할 수 있을까?"라는 고민을 하게 되었습니다. 또한 넷플릭스에서 보고 싶은 영화를 검색했는데 없어서, 어느 OTT에서 제공하는지 알 수 없어 네이버와 구글을 오가며 직접 찾아본 경험도 있었습니다. 구독료를 효율적으로 쓰기 어렵다는 점과 작품이 어디에 있는지 한눈에 알기 어렵다는 점, 이 두 가지 불편을 직접 해결해 보고 싶어 OTT내비를 만들기로 했습니다.

### 2.2 README·한 줄 소개용 (두 문장)

OTT는 서비스가 많고 서비스마다 고유 콘텐츠가 달라, 어느 작품이 어디에 있는지 찾기도 어렵고 구독료를 효율적으로 쓰기도 어렵습니다. OTT내비는 이 두 불편을 직접 겪은 경험에서 출발해, 보고 싶은 작품과 월 예산·시청 시간을 바탕으로 어느 달에 어느 OTT를 구독하면 좋을지 3개월 플랜으로 안내하는 서비스입니다.

### 2.3 면접 구두 답변용 (말하듯이)

"OTT가 워낙 많고 서비스마다 보는 작품이 달라서요. 저도 한 OTT를 쭉 구독해 봤는데, 어느 정도 보고 나면 막상 더 보고 싶은 게 없더라고요. 그래서 구독을 어떻게 하면 몰아서 보면서 본전을 뽑을 수 있을까 고민했습니다. 그리고 넷플릭스에서 영화를 검색했는데 없어서, 어디서 볼 수 있는지 몰라 네이버나 구글로 한참 찾았던 경험도 있었습니다. 이 두 가지 불편을 한 번에 해결해 보고 싶어서 만들게 됐습니다."

## 3. 서비스와 연결하는 말 (필요할 때 덧붙이는 문장)

아래는 `docs/PRD.md`에 정리된 실제 기능과 연결한 문장이다. 면접이나 소개 글에서 "그래서 무엇을 만들었나"를 이어 말할 때 쓴다.

- **어디에 있는지 모르는 문제** → 작품을 검색하면 국내 OTT 7곳의 제공 여부를 **있음 / 없음 / 모름** 세 가지로 보여 주고, 데이터 출처(TMDB·JustWatch)와 데이터 기준일을 화면마다 표시합니다. 확실하지 않은 정보는 "확정"이 아니라 "확인된 범위"로 표현합니다.
- **구독료를 효율적으로 쓰고 싶은 문제** → 보고 싶은 작품을 찜하고 월 예산과 월 시청 시간을 입력하면, 어느 달에 어느 OTT를 구독하면 좋을지 **3개월 롤링 플랜**으로 계산합니다(이번 달만 확정, 다음 두 달은 예상). 한 시즌이 길면 서로 다른 서비스를 이어서 보는 경우까지 반영하고, 꼭 볼 작품 수와 점수, 비용이 같으면 더 일찍 볼 수 있는 쪽을 고릅니다(PRD 5.4).
- 비영리 서비스이며 수익화 요소가 없습니다(TMDB 이용 조건에 맞춤).

## 4. 쓸 때 참고

- 위 문구는 **사실 확인이 끝난 경험담만** 담았다. 수치(사용자 수, 절약 금액 등)나 "많은 사람이 겪는 문제"처럼 근거 없는 일반화는 넣지 않았다. 필요하면 실제로 확인한 근거를 붙여서 쓴다.
- "뽕을 뽑다"는 구어체 표현이라 서면(2.1, 2.2)에서는 "구독료만큼 충분히 이용한다"로 바꿨고, 구두(2.3)에서는 "본전을 뽑는다"로 옮겼다. 원문의 표현이 더 마음에 들면 2.3에서 그대로 써도 된다.
- 질문이 길면 2.3의 첫 두 문장(서비스가 많고 구독이 비효율적이다)만, 짧으면 2.2를 쓴다.
